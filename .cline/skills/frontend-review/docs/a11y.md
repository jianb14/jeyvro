# Accessibility Patterns (Jeyvro Frontend)

Detailed patterns matching the existing components. Read this when reviewing interactive components, forms, or overlays.

## Dialogs / Modals (reference: Modal.jsx)

- Render panel through `createPortal` so it escapes stacking contexts.
- Backdrop: separate `aria-hidden="true"` div handling click-to-close.
- Panel: `role="dialog" aria-modal="true"`.
- Escape: `document.addEventListener("keydown", onKey)` inside `useEffect`, removed in cleanup.
- Scroll lock: `document.body.style.overflow = "hidden"` while open, restored (`""`) on cleanup.
- Close button: icon-only → must carry `aria-label="Close dialog"`.

## Forms (reference: Input.jsx, Checkbox.jsx, Textarea.jsx)

- Generate ids with `useId()`; associate `<label htmlFor={id}>` with the control.
- Errors: set `aria-invalid="true"` on the control and link the message with `aria-describedby={errorId}`.
- Password toggles and similar affordances: `aria-label` reflecting the action ("Show password"), not the current state alone.
- Never disable + rely on placeholder as the only hint.

## Keyboard behavior checklist

| Element | Keys |
|---|---|
| Button | Enter / Space |
| Checkbox / Switch | Space toggles |
| Tabs | Arrow keys optional, but Tab must move into and out of the tablist |
| DropdownMenu / CommandPalette | Escape closes; Arrow keys move active item; Enter selects |
| Overlays | Escape closes; focus is not lost outside the page |

## Color independence

- Alerts, badges, toasts include an icon + text alongside color (see Alert.jsx, Toast.jsx tone maps).
- Rating, Stepper, and progress states must remain meaningful in grayscale.

## Contrast guidance

- The canonical pairs (white on moss-600/danger-600; sand-900 on sand-50; sand-100 on night-900) are the established design — keep them.
- When inventing a **new** pairing, verify it meets WCAG AA (4.5:1 normal text, 3:1 large text/UI components) with a contrast checker before shipping. Do not eyeball it.

## Touch targets

- Interactive elements ≥ 44px (existing scale: `h-10` md, `h-12` lg, `h-8` only for dense/sm controls).
- Adjacent tap targets need spacing (min `gap-2`).

## Manual test walkthrough (run before declaring done)

1. Unplug the mouse: Tab through the whole page — is order logical, is focus always visible?
2. Tab into every overlay; press Escape; confirm it closes and scroll is restored.
3. Trigger a form error; confirm it is announced (aria-invalid + describedby) and readable in dark mode.
4. Toggle dark mode; confirm nothing becomes invisible or low-contrast.
5. Narrow the window to ~360px; confirm no horizontal overflow.
